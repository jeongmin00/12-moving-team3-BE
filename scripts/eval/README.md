# 채팅 콘텐츠 필터 평가

프로젝트 종료 후, 채팅 욕설·개인정보 필터의 성능을 테스트 문장으로 측정하고 개선을 시도한 기록입니다.
필터 구조: 금칙어 정확 일치 → (안 걸리면) 토큰 임베딩 유사도 검색(pgvector, `text-embedding-3-small`).

## 결과 요약

| 테스트 세트 | 조건 | 욕설 탐지율 | 정상 대화 오탐률 |
| --- | --- | --- | --- |
| 기존 세트 (106문장) | D. 프로젝트 종료 시점 (임계값 0.55) | 87.5% | 20.6% |
| | E. 허용어 + 정규화 (0.55) | 95.0% | 2.9% |
| | E + 임계값 0.60 | 92.5% | 2.9% |
| 홀드아웃 2종 합계 (149문장) | D | 86.7% | 39.0% |
| | E (0.55) | 88.3% | 35.6% |
| | E + 임계값 0.60 | 81.7% | 27.1% |

전화번호·계좌번호 필터(정규화 파이프라인)는 세 세트 모두 탐지율 100%였습니다. (기존 세트에서 초기 정규식 45.5% → 100%)

## 확인한 것

1. **임계값 하나로는 욕설과 정상어를 가를 수 없다.**
   기존 세트에서 유사도로만 잡힌 변형 욕설은 0.59–0.77, 오탐된 정상어(병원·씨앗 등)는 0.61–0.77로 점수 구간이 겹쳤습니다.
   짧은 토큰 하나를 임베딩하면 뜻보다 글자 모양이 비슷한 단어끼리 점수가 높게 나옵니다.
2. **규칙 추가(허용어·정규화)는 처음 보는 데이터에서 효과가 작았다.**
   기존 세트 오탐은 20.6% → 2.9%로 줄었지만, 허용어 일부가 이 세트의 문장에서 나왔기 때문에 과대평가입니다.
   홀드아웃에서는 39.0% → 35.6%에 그쳤습니다.
3. **임계값을 올리면 오탐과 탐지를 맞바꾼다.**
   기존 세트만 보고 0.60을 고른 뒤 홀드아웃을 한 번 측정하니 오탐은 27.1%로 줄었지만 탐지율도 81.7%로 떨어졌습니다.
   새로 놓친 욕설은 정규화 규칙이 다루지 않는 변형(매핑 표에 없는 음절, 영문 사이 숫자 대체)으로, 유사도 0.55–0.60에서 간신히 잡히던 것들이었습니다.

→ 다음 단계로는 임계값 조정보다, 점수가 확실한 구간만 차단하고 애매한 구간은 마스킹·관리자 검토로 분리하는 구조가 필요하다고 판단했습니다.
  (필터된 메시지의 원문은 이미 별도 저장하고 있어 검토 흐름과 연결할 수 있습니다.)

## 측정 조건

| 조건 | 내용 |
| --- | --- |
| A | 정확 일치만 (글자 사이 공백·특수문자 삽입 허용) |
| B | A + 유사도 0.82 (초기 임계값) |
| C | A + 유사도 0.55, 자모 토큰 포함 |
| D | A + 유사도 0.55, 자모 토큰 제외 — 프로젝트 종료 시점 |
| E | D + 허용어 구간 제거 + 정확 일치 전 정규화 — 현재 `src` 코드 |

A–D는 개선 전 로직을 스크립트 안에 고정해 재현합니다. E는 `src/utils/content-filter`를 그대로 불러옵니다.

## 테스트 세트

| 파일 | 문장 수 | 작성 시점 |
| --- | --- | --- |
| `content-filter-cases.json` | 106 | 개선 전. 허용어 일부가 이 세트에서 나와 E 수치는 과대평가 |
| `content-filter-holdout.json` | 87 | 개선 규칙과 별도로 작성, 규칙 확정 후에만 측정 |
| `content-filter-cases.holdout.json` | 62 | 규칙 확정 후 작성. 허용어에 없는 정상어와 정규화로 오탐이 날 수 있는 문장을 의도적으로 포함 |

라벨: `profanity`(욕설) / `phone`·`account`(전화·계좌) / `clean`(정상). 욕설 판정 지표의 정상 대화에는 `숫자 포함 정상` 그룹을 제외합니다.

## 실행

```bash
# OPENAI_API_KEY가 .env에 있으면 유사도 조건(B~E)까지 측정, 없으면 A·전화/계좌만 측정 (DB 불필요)
npx ts-node --transpile-only scripts/eval/eval-content-filter.ts

# 테스트 세트 교체
npx ts-node --transpile-only scripts/eval/eval-content-filter.ts --cases scripts/eval/content-filter-holdout.json

# E 규칙에 임계값만 바꾼 조건 추가
npx ts-node --transpile-only scripts/eval/eval-content-filter.ts --thresholds 0.60,0.65
```

- 결과: 기본 세트는 `content-filter-eval-result.md`, 그 외는 `content-filter-eval-result.<세트 이름>.md`
- 임베딩은 `.embedding-cache.json`에 캐시합니다 (git 제외).
- 커밋된 결과 파일은 위 요약 표를 측정한 시점의 스냅샷입니다. 재현에는 API 키가 필요해 결과를 함께 남겼습니다.
